On-chain Metadata 和 IPFS Metadata 有什麼根本差異？各自的優缺點？

On-chain Metadata 顧名思義存在鏈上， IPFS Metadata 則是存在鏈下。

On-chain IPFS Metadata
優點 鏈還在metadata就不會不見 資料可能會被IPFS節點刪除，有機會遺失 缺點
缺點 鏈上儲存成本高 成本友善 優點

On-chain URI

On-chain Metadata 衍生的問題，tokenURI

tokenURI不是要回傳網址嗎？
有網址然後才能拿到網址的 responese 存著 metadata的.json

在On-chain Metadata的作法上，呼叫 tokenURI() 拿到的是DataURL

Data URL

RFC2397 標準，讓資料本身直接塞入 URL 裡的標準。

範例

所以 On-chain Metadata 的 tokenURI() 回傳值是
data:application/json;base64,… 這個意思是一個經過 base64 編碼的 json 檔。

儲存方式 *tokenURI 回傳值
IPFS ipfs://QmXyz.../1.json
中心化伺服器 https://api.example.com/metadata/1
On-chain data:application/json;base64,eyJuYW1lIjoi...

什麼是 Base64 編碼？

Base64 是一種把二進位資料轉換成純文字字串的編碼方式。
編碼方式是將把 bytes 重新切成 6-bit 一組，然後查表換成字元。

Base64 編碼

| M | a | n | （原文字）

| 77 | 97 | 110 | （轉成Ascll）

| 01001101 | 01100001 | 01101110 | (轉乘二進制)

| 010011 | 010110 | 000101 | 101110 | (分成6bit一組)

| 19 | 26 | 5 | 46 | （index，查base64表，換成）

| T | W | F | u | （base64編碼）

為什麼 tokenURI 要回傳 data:application/json;base64,... 格式？

在 ERC721metadata 的說明中， tokenURI 要回傳一個 URI ，而 Data URL 正是 URI 的一種。

如何在 Solidity 中生成 SVG 圖片？字串拼接後如何嵌入 tokenURI？

  1. 用 abi.encodePacked 拼接 SVG 字串
    SVG 是 XML 純文字格式，直接在 Solidity 裡用字串拼出來。如果要處理數字用 Strings.toString() 轉型插入。
  2. SVG → Base64 → image URI（data:image/svg+xml;base64,…）
    把 SVG 字串轉成 Base64，加上 RFC 2397 Data URL 前綴，變成 image URI。
  3. 組 JSON metadata，把 imageURI 嵌入 image 欄位
    照 OpenSea standard，metadata JSON 需要 name、description、image（就是imageURI）、attributes 等欄位。
  4. JSON 再 Base64
    最終 tokenURI 對整個 JSON bytes 做 Base64，加上 data:application/json;base64, 前綴，就是完整 tokenURI。

On-chain Metadata 需要哪些 OpenZeppelin 工具（Base64.sol、Strings.sol）？

Base64.sol 對二進制編碼，必定會用到
Strings.sol 在JSON跟XML可能會用到，例如在XML用變數調整顏色等
